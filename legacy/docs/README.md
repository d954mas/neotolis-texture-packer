# Documentation

This is a minimal routing entry point. The existing documentation tree predates
the project-local workflow and will be classified, verified, and reorganized as
the framework's first separate task. Until that audit is approved and complete,
do not infer authority from a file's directory or age and do not move, delete,
or rewrite documentation opportunistically.

Use this route:

- Start with `../AGENTS.md` for repository invariants and the current authority
  rules.
- For product or architecture questions, read only the relevant sections of
  `ntpacker-master-spec.md`.
- For an affected serialized format or CLI report, inspect the matching file in
  `formats/`.
- Use `decisions/`, code, tests, and Git history when the task needs historical
  or implementation evidence.
- Treat `plans/`, `research/`, and unverified design material as inputs to the
  future audit, not as automatic authority.

The documentation migration itself is intentionally out of scope for the
workflow bootstrap.
